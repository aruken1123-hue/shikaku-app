# 問題を楽に作る方法（調査と方針）

作成: 2026-10-29 ／ 状態: 案1を採用。取り込みツール・条文取得ツール・確認ボタンは作成済み（解説づけは未着手）

## いちばん重いのは「正しいかの確認」
AIの下書きは数秒でできる。時間がかかるのは、人が条文を引いて正誤を確かめる作業。
だから「確認の手間を減らす」ことを軸に方法を選ぶ。

## 調べて分かったこと（2026-10-29 時点）
- **e-Gov 法令API v2**（国の法令データ）: 認証なしで、条・項を指定して条文を取れる。
  例 `https://laws.e-gov.go.jp/api/2/law_data/327AC1000000176?elm=MainProvision-Article_35-Paragraph_6&response_format=json`
  （宅建業法35条6項。2026-10-29 に取得できることを確認）。`asof=YYYY-MM-DD` で過去の時点の条文も取れる。
  JSON 形式は試行版（仕様が変わりうる）。利用規約の本文は未確認。判例は取れない。
- **主な法令ID**: 宅建業法 327AC1000000176／民法 129AC0000000089／都市計画法 343AC0000000100／
  建築基準法 325AC0000000201／国土利用計画法 349AC1000000092／地方税法 325AC0000000226／
  借地借家法 403AC0000000090／区分所有法 337AC0000000069／不動産登記法 416AC0000000123／
  農地法 327AC0000000229／土地区画整理法 329AC0000000119／宅地造成及び特定盛土等規制法 336AC0000000191
- **RETIO の過去問**: 昭和63〜令和7年度の PDF（問題＋最後のページに正解番号）。解説はない。
  R5〜R7 は文字を取り出せる。R4 以前（R2・R3・R4・H30 で確認）は画像で、書き起こしが要る（下の「画像だけのPDF」）。
  無断転載・無断改変は不可。自分の端末だけで使うのは私的使用と考えられる（要確認）。
- **費用**: Claude Code に頼むなら今の定額の中（追加0円）。API でツール化すると1問 数円〜20円程度。

## 3案
| | 案1 過去問が土台（推奨） | 案2 AIで新作を量産 | 案3 手作り中心 |
|---|---|---|---|
| 中身 | RETIO の PDF を取り込む → AI が条文つき解説を付ける → 解きながら確認 | e-Gov の条文だけを根拠に AI が作る → 別の AI で検算 → 食い違いだけ人が見る | スプレッドシートに1行1問 → 変換ツールで JSON に |
| 正解の確かさ | 公式の正解なので確か（古い年度は法改正に注意） | AI 次第。検算で減らすがゼロにはならない | 本人の理解次第 |
| 確認の手間 | 1問2〜3分（理由だけ見る） | 1問3〜5分 | 作るのに1問5〜10分 |
| 公開 | できない（自分の端末だけ） | できる（条文には著作権がない） | できる（市販書を写さなければ） |
| 捨てるもの | 公開・人への配布。解説は AI 製なので確認が要る | 正解の確かさ。判例が根拠の問題は弱い | 量。手間がかかる |

推奨理由: いちばん重い「正解が合っているか」の確認が要らない。AI の誤りが入るのは解説だけになり、
条文の自動表示と解きながらの確認で潰せる。公開用や弱い分野の補強は、あとで案2を足す。

## 案1で作るもの（洗い出し）
1. `tools/import-retio.py` … RETIO の PDF（R6・R7）から問題文・選択肢・正解番号を取り出し、
   `private/takken-R7.json` などの取り込み用 JSON を作る。id は `takken-<科目>-p<年度><問番号>`、
   `source.kind: "past-exam"`、`lawAsOf` は表紙の基準日（例 R7 は 2025-04-01）。
   「正しいもの／誤っているもの」は問題文から判定。図や表のある問題、判定できない問題は一覧に出して手作業に回す。
   科目は問番号の範囲で振り分ける（R7 の範囲は要確認）。
2. **解説づけ** … Claude Code に、取り込んだ問題と e-Gov の条文を渡して `explanation`・`note`・`basis` を書かせる。
   正解は公式のものを固定し、AI には変えさせない。
3. **アプリの追加機能** … 問題の `basis` から e-Gov の条文を取って解説の下に表示する
   （圏外では出ないので、取り込み時に条文を一緒に保存する案も検討）。
   「確認済み」「誤りかも」ボタンと、その印の書き出し。
4. テスト … 取り込みツールの出力が `js/store.js` の検査に通ること、公開用 `data/` に混ざらないこと。

## 作ったツールと手順（2026-10-29）
1. RETIO のサイトから PDF を自分でダウンロードし、`private/` に置く（Git には入らない設定済み。PDF自体は公開しない）。
2. 取り込み用JSONを作る（外から来たファイルなので `python -I`）:
   ```
   python -I tools/import-retio.py private/R7.pdf --out private/takken-R7.json
   python -I tools/import-retio.py private/R6.pdf --year 2024 --out private/takken-R6.json   # --year は省ける（表紙の「令和〇年度」から決める）。付けて表紙と食い違えば止まる
   ```
   - 正解表は文字の座標（行→列）で読み、ちょうど50個読めなければ（欄の欠け・見出しの数の不一致など）エラーで止まり、何も出力しない。
   - 「最も〜」の問題には `noTf: true` を付ける（○×一問一答に出さない。名詞の選択肢の問題などは手で付ける）。
   - 科目は問番号で振り分け（1〜14 kenri、15〜22 seigen、23〜25 zei、26〜45 gyouhou、46〜50 zei＋タグ「5問免除」）。タグに年度（R7 など）が付く。
   - 「正しいもの／誤っているもの／適切…／不適当…はどれか」の普通の問題は `choice`（正解は公式の正解番号から `ok` を決める）。個数・組合せ・問い方を判定できない問題は `single`（正解番号を `answer` に持つ）。
   - 正解が複数・「全員正解」・読めない問題、選択肢が4つ取れない問題は出力から外し、図や表がありそうなページの問題は入れたうえで、最後に警告として一覧に出す。
   - `lawAsOf` は表紙の「令和〇年〇月〇日現在施行」から取る。`reviewed: false`、解説・根拠は空。
3. 形を確かめる: `node tools/check-private.mjs private/takken-R7.json`（アプリの検査と同じ。おかしい問題をすべて一覧にする）。
4. アプリの設定 → 「自分の問題の取り込み」でそのJSONを選ぶ（外部には送らない。UTF-8 で保存されたファイルのみ）。
5. 条文を足す（任意）: `node tools/egov.mjs 宅建業法 35 6` で出るJSONを、問題の `basisText` 配列に足す。e-Gov 法令API v2（認証不要）を、手で動かしたときだけ呼ぶ。大量に呼ばない。法令は取得した日の条文なので、古い年度の問題では `asof` を付ける（`--asof 2025-04-01`）か、法改正に注意する。
6. 解きながら、回答後の画面の「確認済みにする」「誤りかも」で印を付ける。誤りかもの一覧は設定画面にある。

## 画像だけのPDF（令和4年度以前）の取り込み（2026-10-29）
RETIO の令和4年度以前のPDFは紙をスキャンした画像で、`import-retio.py` では文字が取れない。令和5年度は文字入りなので上の手順でよい。
1. ページを画像にする（200dpi・グレー）: `python -I -c "import pymupdf,sys; d=pymupdf.open(sys.argv[1]); [p.get_pixmap(dpi=200,colorspace=pymupdf.csGRAY).save(f'{sys.argv[2]}/p{i+1:02d}.png') for i,p in enumerate(d)]" private/retio-pdf/R4.pdf private/ocr/R4`（先に `private/ocr/R4` を作る。回は `R4`、10月と12月の2回ある令和2・3年度は `R2-10`・`R2-12`。12月の回の表紙には「（12月27日）」のような日付がある）。
2. 内蔵OCRで下読み: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/winocr.ps1 private/ocr/<回>`（Windows 標準の日本語OCR。各ページの `pNN.win.txt` ができる。誤読が多いので照合用）。
3. 書き起こし: AI がページ画像を見て一字一句 `private/ocr/<回>/transcript.txt` に書く（形は `tools/import-retio-ocr.py` の先頭の説明。見本は `private/ocr/R4/transcript.txt`）。印刷の誤字も直さない。
4. 照合: `python -I tools/ocr-diff.py private/ocr/<回> private/ocr/<回>/transcript.txt --out private/ocr/<回>/diff.txt`（一覧には過去問の文が入るので private/ の中に書く）で内蔵OCRとの食い違いを出し、1つずつ画像で確かめて書き起こしの誤りだけ直す。直したらもう一度出して、残りが全部内蔵OCRの誤読であることを確かめ、`review.txt` に記録する。
5. 正解表（最後のページ）は**2人が別々に**画像を読み、10問ずつ5組の列にする（正解なし・複数正解の問は `x`。取り込みから外れる）。50桁の写し間違いは本人の見直しでは気づけない（2026-10-29 に2回起きた）。照合が済んだ列の控えは `private/ocr/answers.txt`。**作り直しのときも、2人目の列は控えから貼らず、正解表の画像から読み直す**（控えを両方に貼ると照合が形だけになる）。
6. 変換: `python -I tools/import-retio-ocr.py private/ocr/<回>/transcript.txt <回> --key-a <1人目の5組> --key-b <2人目の5組> --out private/takken-<回>.json`。2人の列が1文字でも違う、回の名前と表紙（12月の日付の有無・年度）が合わない、50問（x の問を除く）がそろわない・見出しが2回ある、のどれかなら止まり、何も出力しない。
7. 形を確かめる: `node tools/check-private.mjs private/takken-<回>.json`。
