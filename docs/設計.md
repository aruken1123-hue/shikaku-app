# 資格取得アプリ 設計メモ（下ごしらえ）

作成: 2026-10-28 ／ 状態: 方向性の提案段階（実装前）

## 目的
いろいろな資格に使える学習アプリの仕組みを作り、最初は宅建で使う。
アプリ本体と資格ごとの問題データ（JSON）を分ける。

## 3案

| | 案A 既製品に相乗り（Anki） | **案B 専用アプリ・ゴルフナビ型（推奨）** | 案C スプレッドシート中心・同期前提 |
|---|---|---|---|
| 中身 | 無料の暗記アプリ Anki に問題を流し込む。作るのは問題データと変換ツールだけ | ゴルフナビと同じ作り（1つのWebアプリ＋資格ごとのJSON）。4択・○×・復習・成績・残り日数 | 問題も記録も Google スプレッドシートに集め、GAS で全端末を同期 |
| 手間 | 1〜2回分 | 週末2〜3回分（同期を足すなら＋1〜2回） | 案Bの2〜3倍＋GAS 再公開の手作業が続く |
| 捨てるもの | 本番形式の4択・模試・宅建向け成績表 | 最初の版では端末間の自動同期（手動の書き出し・読み込みで移す） | 仕組みの単純さ・応答の速さ（2〜45秒待つことがある） |

推奨理由: ゴルフナビの版番号・圏外対応・データ点検テスト・PC編集サーバーがほぼそのまま使え、
宅建に必要な4択・模試・残り日数を作れる。記録を「追記だけの形」にしておけば、案Cの同期を後から足せる。

## 本番の場所（アプリ開発ルール A1・A2）— 未決
- 配信先: GitHub Pages（新しいリポジトリ）を想定。URL・リポジトリ名は未決
- 私の担当範囲: Git への送信まで／公開まで のどちらか未決
- 公開してよいのは自作・確認済みの問題だけ。過去問は `private/`（Git に入れない）

## 問題データの著作権
- RETIO（宅建試験の実施団体）の過去問は「私的使用等を除き無断転載不可」「無断改変不可」。
  公開の場所（GitHub Pages）には置かない。端末内で自分だけが使う範囲は私的使用と考えられるが要確認
- 条文そのものには著作権がない（著作権法13条）→ 根拠として載せてよい
- 市販問題集は取り込まない
- 法改正で正解が変わるので、問題ごとに「どの時点の法令が基準か」（`lawAsOf`）を持つ
- AI 下書きの問題は、人が条文で確かめたもの（`reviewed: true`）だけを本番扱いにする

## データの形

### 資格の定義 `data/takken/exam.json`
```json
{
  "schemaVersion": 1,
  "id": "takken",
  "name": "宅地建物取引士",
  "revision": 1,
  "updated": "2026-10-28",
  "exam": { "questions": 50, "minutes": 120, "choices": 4, "passLineHint": 36, "maxPoints": 50 },
  "nextExamDate": "2027-10-17",
  "subjects": [
    { "id": "kenri",   "name": "権利関係",     "count": 14 },
    { "id": "gyouhou", "name": "宅建業法",     "count": 20 },
    { "id": "seigen",  "name": "法令上の制限", "count": 8 },
    { "id": "zei",     "name": "税・その他",   "count": 8 }
  ],
  "questionFiles": ["q-kenri.json", "q-gyouhou.json", "q-seigen.json", "q-zei.json"]
}
```
- `nextExamDate` は見込み（10月第3日曜）。正式日程の公表後に確認し、設定画面でも直せるようにする
- `passLineHint` は年で変わる目安。画面で直せるようにする
- `maxPoints`（任意）は満点。無ければ「1問1点」で `questions`。合格目安の上限検査と「36点 / 50点」の表示に使う（配点が違う資格用）
- 模試は `subjects[].count` どおりに出題する → 他の資格でもそのまま使える

### 問題1問
| 項目 | 内容 |
|---|---|
| `id` | 公開データは `<資格ID>-<科目ID>-<4桁>`（例 `takken-gyouhou-0001`）。学習記録の目印なので一度付けたら変えない・使い回さない。画面から取り込む private の問題は `<資格ID>-<科目ID>-p<4〜8桁>`（例 `takken-kenri-p0001`、過去問は `takken-kenri-p202501`）の形だけ許可し、公開データと衝突しないようにする |
| `subject` / `tags` | 科目ID／例 `["重要事項説明","35条"]` |
| `type` | `choice`（4択。選択肢の `ok` から正解を計算）／`single`（選択式で、正解の番号 `answer` を持つ。個数問題・組合せ問題・問い方を判定できない過去問用）／`truefalse`（○×）|
| `noTf` | 任意。`true` なら○×一問一答に出さない。「最も不適当なもの」のように、選択肢を1つずつ正誤にすると意味が変わる問題に付ける（過去問の取り込みツールは `ask` に「最も」があれば自動で付ける。名詞の選択肢の問題は手で付ける）。4択演習・復習・間違いには出る |
| `answer` | `single` だけ。正解の選択肢の番号（0始まり）。選択肢は `{ text, note? }` だけで `ok` は持たない。4択演習・間違えた問題・復習には出るが、○×一問一答には出ない |
| `ask` | 問い方の表示用の文字列（例 `正しいもの`／`誤っているもの`／`適切なもの`／`不適切なもの`）。自由に書ける |
| `pick` | 任意。`true`＝記述が正しい（適切な）選択肢を選ぶ問題、`false`＝誤り（不適切）を選ぶ問題。無ければ `ask` から推定（正しい・適切→true、誤・不適切→false。「正しくない」「適切でない」「誤っていない」のように否定が付けば逆）。どちらでも決まらなければ不正データ |
| `stem` | 問題文 |
| `choices` | `[{ text, ok, note }]`。`ok` は記述そのものが正しいか。正解番号は `pick` と `ok` から計算（`pick` が true なら ok:true がちょうど1つ、false なら ok:false がちょうど1つ）→ 4択1問から○×が4問自動でできる。**公開したあとは選択肢の順番を変えない**（下の「選択肢の順番」参照） |
| `explanation` / `basis` | 解説／根拠条文（例「宅建業法35条1項」） |
| `source` | `{ kind: original / ai-draft / past-exam / textbook-ref, ref, url }` |
| `lawAsOf` | どの時点の法令が基準か |
| `reviewed` / `reviewedAt` | 人が確かめたか。未確認は模試に出さない。画面には「未確認」バッジ（過去問は正解が公式なので「解説未確認」）。端末で「確認済みにする」を押すとバッジが消える（下の「確認の印」） |
| `basisText` | 任意。根拠条文の本文 `[{ ref, lawId, elm, asOf, text }]`。`node tools/egov.mjs <法令名> <条> [項]` で作る。回答後の解説の下に「条文を見る」（開閉式）で表示。アプリ本体は e-Gov に通信しない |
| `status` | `active`／`retired`（法改正で使えなくなった問題を隠す。記録は残す） |
| `revision` / `updated` | 問題の版 |

## 選択肢の順番（仕様）
- ○×の学習記録の項目ID（`itemId`）は `問題id#選択肢番号（0始まり）` なので、公開後に選択肢の順番を入れ替えると、過去の記録が別の選択肢にずれる。
- そのため **公開後は選択肢の順番を変えない**。直したいときは、新しい id の問題として作り直し、旧問題は `status: "retired"` にする（記録は残り、出題されなくなる）。
- 選択肢に固有のIDを持たせる案は、今回は見送り（データが重くなるため）。必要になったら `schemaVersion` を上げて検討する。

## 確認の印（確認済み／誤りかも）
- 回答後の画面の「確認済みにする」「誤りかも（任意で一言メモ）」で、`{ id, questionId, at, status: "ok" | "suspect", note, device }` を IndexedDB（`reviews`）に追記する。問題ごとに最新の1件が有効。
- 表示: 端末で ok にした問題は「未確認」バッジを消す。suspect は「誤りかも」バッジ。過去問（`source.kind` が `past-exam`）の未確認問題は「解説未確認」。
- 設定画面に「誤りかもの問題」の一覧（問題文の頭・メモ・日時）。記録の書き出しに `reviews` も入り、読み込みでは id で重複を除いて合わせる（学習記録と同じ方式）。

## 過去問の取り込み（private）
- 公開してはいけない過去問は `private/` に置き、アプリの設定画面から取り込む。取り込む問題の id は `<資格ID>-<科目ID>-p<4〜8桁>`（過去問は `p<西暦年><問番号2桁>`、例 `takken-kenri-p202501`）。
- RETIO の PDF からは `tools/import-retio.py` で作る（手順は `docs/問題作り.md`）。`explanation`・`basis` は空でよい（private のみ。公開 `data/` は今までどおり `basis` 必須）。

## 復習の箱（Leitner）の進め方
- 箱1〜5、次回までの間隔は 1・3・7・14・30 日（日付の境目は端末の現地時刻）。
- 不正解 → 箱1に戻り、次回は翌日。
- 正解 → その項目を **初めて答えたとき、または次回期限の日以降のときだけ** 箱を1つ進める（最大5）。次回は「答えた日＋進んだ先の箱の間隔」。
- 期限前の正解（同じ日の繰り返し、間違えた直後のやり直しなど）は、箱も次回期限も変えない。
- 「間違えた問題」の一覧は、従来どおり「直近の回答が不正解のもの」。

## 学習記録
- 回答1回ごとに1行を足すだけの形（ID・問題ID・日時・正誤・モード・端末名）。復習の箱や正答率は毎回そこから計算
- 複数端末の記録は「IDで重複を除いて足し合わせる」だけで合わせられる（手動の移動でも、後の GAS 同期でも同じ）
- 保存先は IndexedDB（ブラウザの大きめの保存場所）を推奨。`navigator.storage.persist()` で消されにくくし、定期的な書き出しを促す
- GAS の URL はコードに書かず設定画面で入力（ルール B4）
